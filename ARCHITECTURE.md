# Architecture

Tibay is a **modular monolith**: one Next.js application, deployed as one Cloudflare Worker, with one D1 database and one R2 bucket. There are no queues, no KV, no Durable Objects and no separate services.

## Stack (as implemented)

| Concern | Choice | Notes |
|---|---|---|
| Framework | Next.js 16 (App Router, React 19, TypeScript) | Changed from Astro at the owner's request during the build. |
| Runtime / hosting | Cloudflare Workers via `@opennextjs/cloudflare` | `custom-worker.ts` wraps the generated worker to add the Cron handler. Production builds use **webpack** (`next build --webpack`): Turbopack duplicated shared server code per route and exceeded the 3 MiB free-plan bundle limit (4.8 MiB vs 2.28 MiB gzipped). |
| Database | Cloudflare D1 (SQLite) + Drizzle ORM | Migrations in `migrations/`, generated by `drizzle-kit`, applied by `wrangler`. |
| File storage | Cloudflare R2 (private bucket) | Images are served through the Worker at `/img/...`. |
| Auth | Better Auth (email + password, email verification, TOTP 2FA, admin role/ban) | Sessions and rate limits are stored in D1. |
| Bot protection | Cloudflare Turnstile | Sign-up, sign-in, password reset, inquiry, report and contact forms. |
| Payments | PayMongo Checkout Sessions + webhooks | Prepaid periods with manual renewal (see *Billing*). |
| Email | Resend HTTP API (plain `fetch`, no SDK) | Logged to the console when no key is set in development. |
| UI | Tailwind CSS v4, shadcn-style components on Radix primitives, Lucide icons, Sonner toasts | Components are hand-written in `src/components/ui`. |
| Charts / tables | Recharts, TanStack Table v9 | Admin only. |
| PDF / QR | jsPDF + jspdf-autotable, `qrcode` | Loaded on demand, run entirely in the browser. |
| Tests | Vitest (unit + integration), Playwright (e2e) | See `TESTING.md`. |

### Module boundaries

- `src/lib` has no server or framework imports. The same code computes quotation totals in the browser (live preview, PDF) and on the server (stored totals), so they cannot disagree.
- `src/server` is never imported by client components (`server-only` enforces this at build time).
- Route handlers are thin: parse → call a `src/server` function → return. All authorisation lives in `route()` and in the server functions, not in the UI.

## Request flow

```
Browser ──► Cloudflare Worker (custom-worker.ts)
              └─► OpenNext handler ─► Next.js App Router
                     ├─ Server Components  ─► src/server/* ─► D1 / R2
                     └─ Route Handlers     ─► route() ─► src/server/* ─► D1 / R2 / PayMongo / Resend
Cron Trigger ──► custom-worker.scheduled ─► POST /api/cron/daily (Bearer CRON_SECRET)
PayMongo ──► POST /api/webhooks/paymongo (HMAC signature)
```

Every page is rendered on demand (`export const dynamic = 'force-dynamic'` in the root layout) because each one reads request-scoped Cloudflare bindings. Consequently no ISR cache, KV namespace or R2 cache bucket is needed. Static assets under `/_next/static` are served by Workers Static Assets with immutable caching and do not invoke the Worker.

## Key design decisions

### No customer dashboard
Owners edit from their own profile page (`/p/username`): an owner-only bar opens dialogs for profile details, images and projects. Navigation to quotations, subscription and settings lives in that bar and in the account menu. The server decides `isOwner`; the edit controls are simply not rendered for anyone else, and every mutation re-checks ownership.

### Plans and entitlements
- Prices and limits live in `DEFAULT_PLAN_CONFIG` (`src/lib/plans.ts`) and can be overridden at runtime by a Super Admin (stored as JSON in `settings`, validated by the same Zod schema).
- **Premium is derived, never stored as a flag**: a user is Premium iff `subscriptions.status = 'active' AND current_period_end > now`. An expired period is Free immediately, even before the daily job marks it `expired`.
- Limits are enforced in SQL in the same statement as the insert (projects, photos) or as a conditional upsert (monthly quotation counter), so concurrent requests cannot exceed a limit.
- **Downgrade never deletes**. Over-limit projects/photos and the cover photo are hidden from visitors; quotation history beyond the current month is locked. Everything returns on renewal.

### Quotations
- Stored in D1 with line items as JSON. Totals are recomputed on the server on every save; client totals are ignored.
- Money is integer centavos; quantities allow three decimals; percentages are basis points. Order of operations: subtotal → discount (capped at subtotal) → tax on the discounted amount.
- "3 / 50 PDF quotations per month" is enforced on **creating** a quotation (including duplicates), counted per calendar month in Philippine time. Because PDFs are generated in the browser, the saved quotation is the unit the server can control. Deleting does not refund quota.
- Custom branding: the server only sends the logo URL to Premium accounts, and adds the "Made with Tibay" footer flag for Free accounts.

### Billing (PayMongo)
PayMongo's Subscriptions API requires account activation by PayMongo and was not assumed. Tibay sells **prepaid periods** through **Checkout Sessions** (GCash, Maya, cards, GrabPay, QR Ph):

1. `POST /api/billing/checkout` — the server reads the price from configuration, inserts a `pending` payment and creates a Checkout Session with `Idempotency-Key` and `reference_number` = our payment id.
2. The user pays on PayMongo's hosted page.
3. `checkout_session.payment.paid` webhook → signature verified → the session is **re-fetched from PayMongo's API** → `applyPaidCheckout()`.
4. In parallel, the return URL makes the browser call `POST /api/billing/verify`, which performs the same server-side lookup (covers a delayed webhook). The success URL by itself grants nothing.
5. `applyPaidCheckout()` runs two guarded statements in one D1 transaction (extend subscription, claim payment). Re-delivery, replay and webhook/return races are no-ops. Amount, currency and live/test mode must match what the server recorded.

Renewal is manual: a reminder email is sent `renewalReminderDays` before the end; paying early stacks onto the remaining time. "Cancel" stops reminders and keeps access until the period ends. Refunds are issued in the PayMongo dashboard; the `payment.refunded` webhook records them and revokes the period a full refund paid for.

If automatic recurring billing is enabled on the PayMongo account later, it can be added behind `src/server/billing.ts` without changing the entitlement model.

### Images
The browser resizes (max 1920 px) and re-encodes to WebP (JPEG fallback) before upload, which also strips EXIF/GPS data. The server checks size (≤ 1.5 MB), sniffs magic bytes (JPEG/PNG/WebP only), generates the key itself (`kind/userId/uuid.ext`) and stores it in R2. `/img/[...key]` serves with a one-year immutable cache, `nosniff` and a locked-down CSP.

### Daily maintenance (cron, 02:15 Manila)
Mark lapsed subscriptions expired and email the owner · send renewal reminders · close abandoned checkouts · delete orphaned R2 objects (one page per run) · prune expired sessions, verification tokens, rate-limit rows and old webhook ids.

## Cost profile

Designed to run on free tiers: Workers Free, D1 Free, R2 Free, Turnstile, Resend Free. See `DEPLOYMENT.md` for the limits that matter and the one case where the paid Workers plan is recommended (CPU time for password hashing).

## Out of scope (future enhancements)
Real-time messaging, job marketplace, bidding, GPS/maps, ratings and reviews, AI features, native apps, escrow, project management, microservices.
